# G2 second review: skeptical biostatistician on frozen model v1.0

A `clinova-reviewer` subagent reviewed model v1.0 read-only at hour 6.1. It acted as a skeptical Regeneron biostatistician and had `docs/metrics.json`, `docs/metrics_detail.json`, `docs/predictions.csv`, `docs/model_manifest.json`, `docs/replay.json`, the figures and the `clinova/model/` and `clinova/loop/` code. Its scratch scripts are copied verbatim into `docs/reviews/G2_scripts/` (r1–r7). They read the live database, so a re-run on a later snapshot will move a little.

The reviewer saw the evaluation written at 04:36Z (354 accrual test trials). The final `metrics.json` (04:44Z) has 359, because ingestion was still adding test trials. Its numbers below are quoted as it reported them. The integrator's own numbers are in `docs/gate2_report.md`.

## The five weakest points, and what G2 did

**1. The accrual model is not shown to beat "is the sponsor industry?".**
- The reviewer built a one-line rule from train rates (non-industry 13.8%, industry 4.1%, r7.py). On test it reached AUC 0.673 and Brier 0.0834. The model reached AUC 0.705 and Brier 0.0837.
- Model minus rule, paired: AUC difference CI [-0.033, +0.095]; Brier difference CI [-0.0023, +0.0029].
- Brier skill against predicting the base rate for every trial: 3.6%, CI [-0.6%, +6.8%].
- **Fixed (cheap):** `evaluate` now writes a `sponsor_only` reference per target into `docs/metrics_detail.json`, so the comparison is part of every run.
- **Limitation to show:** "Accrual-failure ranking is above chance (AUC 0.70, 95% CI 0.62–0.77), but it is not shown to beat sponsor type alone or a simple logistic model."

**2. Probabilities are compressed, and the demo trial is a miss for accrual.**
- Served test p never exceeds 0.218. 15 of the 34 accrual failures score below the 9.6% base rate.
- The demo trial NCT03232892 was terminated for low accrual. It gets accrual p 0.072, the 50th percentile of all test trials and the 23rd percentile among failures (`docs/demo_results/NCT03232892.json`).
- **Fixed (cheap):** demo results now carry `test_percentiles`, so the UI and slides can show a rank instead of a "high risk" label.
- **Limitation to show:** "Predicted accrual-failure risk ranges from 0% to 22%; about half of the real failures scored below average. The demo trial is not an accrual-model success."

**3. The shortfall model has no skill, and its label mostly restates early termination.**
- AUC 0.600 vs logistic 0.608; paired difference -0.008, CI [-0.049, 0.034].
- Brier 0.2515 is worse than predicting the test base rate for every trial (0.2479). Calibration slope 0.65.
- 120 of the 190 test positives (63%) are trials that stopped early: all 28 withdrawn trials and 92 of 113 terminated ones (r5.py).
- **Not fixed. Limitation to show:** "Shortfall prediction is not validated: it does no better than the base rate." T32 should mark it "not validated" in the UI or hide it.

**4. The test set holds only trials that have already ended, so it is biased toward early stops.**
- Test n per start year falls from 71 (2018) to 15 (2024). Accrual-failure prevalence is 19% for 2022 starts vs 6% for 2019; mean served p stays near 0.085.
- A classifier on the same 19 features separates train from test with AUC 0.862 (r6.py).
- **Fixed (cheap):** `metrics_detail.json` now reports AUC by start period. Final file: 2018–2019 starts AUC 0.604 (143 trials, 12 failures; baseline 0.651); 2020+ starts AUC 0.750 (216, 22; baseline 0.662).
- **Limitation to show:** "Tested only on trials that started in 2018 or later and have already ended. Recent trials that are still running are missing, so early stops are over-represented. On the least censored years, 2018–2019, accrual AUC is 0.60 with 12 failures."

**5. Replay and learning-loop evidence is thin, and it counts trials several times.**
- The 1,736 scored windows are 324 unique trials, each scored about 5.4 times, with 28 unique failures.
- Counting each trial once, the retrained Brier is 0.0797 vs 0.0770 frozen. AUC is 0.674 vs 0.655, with no CI (r3/r4.py).
- 29 of 48 monthly AUC points rest on 3 or fewer positives.
- By design (T21 contract, `loop/data.py`), the updated arm learns only from pre-2018 starts whose outcome arrives during the replay.
- **Not fixed. Limitation to show:** "Retrospective replay with 28 unique failures: monthly retraining did not improve on the frozen model."

## Checks that held up
- Every row of `predictions.csv` reproduces from the v1.0 bundle (max |Δp| about 1e-16). T26 Major 1 is closed.
- Relabelling: 115 of the 136 train accrual positives come from the 909 month-only trials, 92 of them from the keyword rule. Training only on exact-date trials (21 positives) still gives test AUC 0.677 vs 0.701. So the labeller mix does not explain the AUC.
- Dropping the 264 train trials first registered after enrollment had started gives 0.696. Late registration does not explain it either.

## Minor
- Data were still loading, so headline numbers carry their snapshot time (`metrics.json` `generated_at`).
- The manifest's train-table hash differs from the one stored in the bundle: 22 train trials were labeled after training and are not in v1.0. `model_manifest.json` lists the ids v1.0 actually used.
- The logistic baseline uses 7 of its 10 named features in v1.0, because 3 are parse-dependent. The code comment now says so.
