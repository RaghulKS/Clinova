# T21 handoff

Status: partial; final T22 model integration remains pending.

## What works

- Prediction ledger stores probabilities, intervals, model version, context and UTC
  timestamp. Feedback stores accept/reject, persona rating and comments with user identity;
  invalid inputs fail before writes and same-key retries cannot overwrite a decision.
- `ledger.ensure_audit_view()` installs the full outer Audit view. Only explicit
  prediction-target feedback joins a prediction; unrelated feedback stays independent.
- Checker fetches fresh CT.gov responses in a temporary private cache, preserves saved
  registration features, reuses T11 mapping/history/label rules, and records exact dated
  ended outcomes. It never writes T11's trials table. Unknown labels remain unknown.
- Matching pre-outcome predictions are scored once. Fixture and replay predictions are
  excluded from operational scoring. The threshold counts newly labeled trials across
  invocations, retrains at 25 by default, and atomically persists a placeholder bundle and
  its checkpoint under DATA_DIR/loop.
- Full 2020-01 through 2023-12 replay ran against Tiger Cloud. Both arms use identical
  fixed placeholder settings and first-version features. Freeze is 2019-12-31. Training
  remains restricted to pre-2018 starts, known labels and registration/outcome cutoff.
  Each month is scored before its new outcomes are learned. Unknown labels and future
  registrations are excluded. Deterministic per-run IDs make repeat writes idempotent.
- Historical ledger scores were materialized with the required autocommit refresh.
  `docs/replay.json` and visually inspected `docs/figures/replay.png` are real script outputs.

## Stubbed / provisional

The T22 branch was absent on origin at the integration checkpoints. The task-permitted
logistic placeholder lives entirely in `clinova/loop/_model.py`, using the shared
train(df,cfg) bundle shape. It is explicitly marked in model versions, plot and summary.
There is no silent automatic fallback from a future T22 failure. Gate 2 must perform the
swap described in `docs/contract_changes/T21.md` and rerun the replay.
The checker's placeholder checkpoint does not replace the API's future final T22 bundle;
the integration must publish T22's saved/latest model after successful retraining.

## How to run

From this worktree with Git Bash, PATH=/usr/bin:/mingw64/bin:$PATH:

```sh
export GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=safe.directory
export GIT_CONFIG_VALUE_0=C:/Users/rghls/Desktop/Clinova/Clinova/.worktrees/T21
uv sync
CLINOVA_MODE=live .venv/Scripts/python.exe -m clinova.loop check --limit 3
.venv/Scripts/python.exe -m clinova.loop replay
.venv/Scripts/python.exe -c 'from clinova.loop.ledger import ensure_audit_view; ensure_audit_view()'
.venv/Scripts/python.exe -m ruff check .
.venv/Scripts/python.exe -m pytest -q
```

On this managed Windows host the Store Python interpreter requires elevated authorized
execution; direct sandbox execution reports a missing interpreter. No credentials are
printed. Settings are read only through common/config.py. The per-process safe-directory
setting above lets config's Git lookup find the main clone under the elevated account;
without it Git's ownership check causes config to fall back to the worktree root.

## Decisions / open issues

- Completion/termination dates are retrospective event-time proxies as requested, not
  historical public-availability timestamps. Later CT.gov corrections may affect these
  labels. This replay is provisional event-time evidence, not a publication-time backtest.
- In contrast, T11 initial outcomes use current-posting dates. Replay uses exact completion
  dates for a consistent requested event-time comparison; that distinction is explicit.
- Do not train on post-2018 static holdout trials, even after their outcomes arrive.
  Newly observed pre-2018 outcomes update the model. No hyperparameters were selected
  using replay/test outcomes.
- Missing exact completion/start/registration dates and unknown amendment labels reduce
  coverage. Checker cannot repair missing trial-table metadata; T11 owns that refresh.
- The checker status event marks a completed inspection; unknown labels are not fabricated
  or repeatedly retried after that event. Later evidence enrichment remains T11's job.
- Audit view SQL must be added to the integrator-owned base schema at Gate 2; exact SQL
  is in `docs/contract_changes/T21.md`.
- Feedback follows v1's existing free-text user identity, without authentication.
- No scheduler, extra dependencies, test-split training or T11/T12 lifecycle changes.
