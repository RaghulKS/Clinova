# T15 handoff: API and app shell on fixtures

Branch `task/T15-app-shell`. Owns `clinova/api/`, `clinova/app/`, `tests/api/`, `tests/app/`, `docs/screens/`.

## What works
- **API** (`clinova/api/main.py`, FastAPI): `GET /health`, `POST /protocols/parse`, `POST /runs` (202, returns `run_id`), `GET /runs/{id}`, `GET /trials/{nct}/backtest`, `POST /optimize`, `POST /feedback`, `GET /validation`, `GET /replay`, `GET /pulse/{nct}`, `GET /audit`. Each calls the real module and falls back to `tests/fixtures` on `NotImplementedError` (or `LiveUnavailable`: database unreachable). Fallback responses say `source: fixture`; `RunStatus.message` names the stages that used fixtures.
- **Runs**: `POST /runs` starts a thread that walks parse, cohort, screen, agents, score, flags, optimize (`clinova/api/runs.py`). Stage by stage fallback; any other exception marks the run `failed` with its message. `edits` in the request are applied before running (the accept-and-re-run path). Local `apply_edits_local` shim for rule and visit edits until `simulate.screen.apply_edits` exists (it is tried first).
- **App** (`clinova/app/`, Streamlit, talks only through `client.py`): paste text or load an NCT ID; editable rule table (field, operator, value, unit, source text, lock toggle; unparseable rows highlighted amber); Run Clinova with stage progress; three panels (Funnel with the biggest exclusion highlighted, Risk with three cards plus where/why/what-to-do flags, Fixes with ranges, dollar value, precedents, Accept/Reject posting to `/feedback`, then a before/after table); backtest reveal timeline when started from an NCT ID; tabs Validation, Replay, Community Pulse, Audit log. "Fixture data" tag whenever `source == fixture`.
- **Screenshots**: `docs/screens/01..09-*.png` at 1920 wide, produced by `python -m clinova.app.screenshots` (needs both servers running and `uv run playwright install chromium` once). Looked at all of them and fixed what was off (theme colour, table height, collapsing inputs, clipped axis title).
- `make check` passes: 99 tests (23 route tests in `tests/api`, 12 module/client tests in `tests/app`).

## What is stubbed or fixture
- Every engine stage, the ledger, and the backtest (`live.backtest` raises `NotImplementedError` until T25) run on fixtures today. Fixture numbers are illustrative, never results (honesty rule); the Validation and Replay tabs say so.
- Fixture mode ignores edits to the rule table for the funnel, risks and fixes (they are static). The reviewed protocol is still what `result.protocol` returns.
- After Accept, the before/after table shows the optimizer's estimates (basis "optimizer estimate") when the re-run is fixture, and real re-run values (basis "re-run") once the engine is live.
- Unknown NCT IDs return 404 while offline; only `NCT99999901` has fixture data.
- Fixture predictions and feedback live in memory (`clinova/api/audit.py`) and vanish on API restart. With the ledger and database up they go to `record_prediction` / `record_feedback`.

## How to run
```
CLINOVA_API_NO_DB=1 uv run python -m clinova.api --port 8000      # API (omit the env var when the DB is up)
CLINOVA_API_URL=http://127.0.0.1:8000 uv run python -m clinova.app  # app on :8501
uv run python -m clinova.app.screenshots --url http://127.0.0.1:8501
```
Env knobs: `CLINOVA_API_NO_DB=1` skips the database probe; `CLINOVA_FIXTURE_DELAY` (default 0.4 s) pauses on each fixture stage so progress is visible (tests set 0).
