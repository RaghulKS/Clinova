# T14 handoff

Status: partial under the task's behavior-check fallback. Interfaces, persistence, CLI and surrogate are implemented; strict three-level enrollment monotonicity is not established.

## What works

- Plain-language offer includes purpose, assignment, arms, all scheduled visit days/procedures/hours/travel, total duration and cumulative burdens; unknown support stays unknown.
- Async concurrent batches of 25 through common.llm, deterministic prompts, three bounded attempts for missing personas. Response IDs, duplicates, schedule bounds and empty reasons are checked. Sync wrapper refuses a running event loop.
- Runner calls the owned T13 cohort/screen interfaces, samples eligible personas by seed, computes the shared summary, and atomically persists one sim_runs row plus one persona_outcomes row per screened person. Unsampled enrollment remains NULL.
- Fitted logistic surrogate uses five schedule-burden features and eight persona traits, imputes from observed training medians, supports constant targets, and uses JSON persistence. Dropout is conditional on enrollment and weighted by enrollment probability. No heuristic replaces missing model artifacts.
- CLI batch dry-run prints nominal/worst request estimates and estimated agent tokens without database/network calls; live batch/run uses first-registered trial fields through shared parsing/visit estimation, caps via common.llm budget, and skips previously completed trial/version/model/seed combinations.

## How to run

- `uv run python -m clinova.simulate batch --n-trials 10 --seeds 2 --max-calls 200 --dry-run`
- After T12/T13 merge and ingestion: `uv run python -m clinova.simulate run --trial NCT... --seeds 1 2`
- Explicitly live synthetic acceptance: `uv run python tests/simulate/run_sanity.py`
- `Surrogate.fit(outcomes_df)` requires observed persona_outcomes rows joined with the five BURDEN_COLUMNS or a `protocol` column of ParsedProtocol/dicts. Save/load default artifact: DATA_DIR/models/surrogate.json.

## Decisions

Use existing sklearn logistic regression and JSON coefficients; add no dependencies. Use fixture reference screen only in opt-in acceptance since T13 is parallel, with no production fallback that could disguise a stub. Keep conditional dropout and unsampled outcomes distinct. Stop after the second prompt at the scope-freeze/deadline window; retain the best prompt and report mixed monotonicity under the named fallback. No shared-file change is required.

## Open issues and limits

- v2 dropout rises across all burden levels for both seeds; enrollment falls light-to-heavy for both seeds but medium exceeds light for seed 1. Do not claim full monotonicity or real-world clinical validity.
- The current task base still contains T12/T13 stubs. Real ingested-trial CLI→parser→cohort integration is deferred to Gate 1, not claimed verified here; runner real-row evidence uses synthetic fixture adapters and live LLM calls.
- The common.llm budget check is shared and concurrent; its existing in-flight overshoot caveat also applies to the CLI max-calls cap. Printed token counts are fixture-based estimates; parse tokens and transport retries vary.
- Surrogate accuracy on held-out or real outcomes is unmeasured. T24 should refit on its broader runs and persist protocol burden joins. The v2 initial timing had a 34ms maximum under concurrent work; final optimized timing is reported above without claiming a hard real-time guarantee.
