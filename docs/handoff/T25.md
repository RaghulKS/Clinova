# T25 handoff: API and app wiring

Branch `task/T25-api` (T15 shell merged, then `origin/main` at gate/1 merged; main's version won outside `clinova/api` and `clinova/app`). Owns `clinova/api/`, `clinova/app/`, table `drafts`, `tests/api/`, `tests/app/`, `docs/screens/`.

## What works
- **POST /runs** (from T15, kept): background thread, stage by stage (parse, cohort, screen, agents, score, flags, optimize). Every score is logged through `loop.ledger.record_prediction` with context `live` (or `backtest`, or `fixture`); when the ledger is a stub or the database is down it goes to the in-memory audit.
- **Live run verified** on the demo trial NCT03232892 (database up, live Gemini or cache): parse, cohort, screen and agents ran the real modules (about 20 s); score, flags and optimize used fixtures (T22/T23 not merged), so the run says `source: fixture` and `Fixture data used for: score, flags, optimize.`.
- **GET /trials/{nct}/backtest** (`clinova/api/backtest.py`): loads the trial, parses the FIRST registered version only (`protocol_from_trial`), runs the pipeline synchronously with context `backtest`, attaches `trial_versions` events and rule changes (parse of the current text, `parse.diff.diff_rules` on rule lists). Cached per trial in memory; one build per trial at a time. Verified live on NCT03232892: rule changes prior_platinum removed, cardiac_condition removed, prior_lines added (same as G1's report). `events` is empty because `trial_versions` has 0 rows (T11 history pass not run yet). Falls back to the fixture backtest for NCT99999901 or when the database is unreachable.
- **POST /fixes/accept** (new, `AcceptRequest` / `AcceptResponse`): logs the accept via `record_feedback` (memory fallback), applies the fix's edits (`apply_edits_local`), then the fast re-run in `clinova/api/quick.py`: re-screen the cached cohort per seed, `Surrogate.score` before and after, scale the run's own agent rates by the surrogate's relative change, re-score with `model.predict.score`, diversity via `simulate.diversity`. No Gemini calls (tested by stubbing `common.llm`). Returns before and after `Measures` and `basis`: `quick_rerun`, or `optimizer_estimate` (the fix's own deltas; used while any stage is missing). Locked or unknown edit target gives 422.
- **drafts table**: pasted text parsed by `/protocols/parse` or `/runs` is saved (`live.save_draft`, best effort, upsert) with its parse.
- `/validation`, `/replay`, `/pulse`, `/audit`: unchanged from T15 (read `docs/metrics.json`, `docs/replay.json`, `docs/pulse/<id>.md`, ledger tables); T16 was cut so the pulse says "not run".
- **Fallbacks**: `live.FALLBACK_ERRORS` = `NotImplementedError`, `LiveUnavailable`, `CacheMiss` (demo mode) and `BudgetExceeded`. A stage that raises one uses its fixture and the run is tagged. Fixture flags and fixes are NOT attached to a non-fixture protocol (they name the fixture's rule ids; accepting one would edit the wrong rule), so a real trial shows "Fix suggestions are not available yet" until the optimizer is merged. Fixture risk scores are still shown on real trials, tagged "Fixture data".
- **App**: Accept now calls `/fixes/accept` and shows the before and after table with a Basis column (re-run vs optimizer estimate); "not estimated" where the optimizer gives no number; backtest call timeout raised to 15 minutes (a first live backtest runs the whole pipeline). Progress view, reveal timeline and the "fixture data" tag unchanged. Screenshots retaken in `docs/screens/01..09`, looked at them; only 04 predates the last tweak (before/after "Eligible" row now uses the funnel, to match the funnel panel).
- `make check`: 247 passed (new: `tests/api/test_wiring.py`, one client test in `tests/app`).

## What Gate 2 must swap or check
1. `live.score`, `live.flag_criteria`, `live.optimize` already call `model.predict.score(protocol, sim=sims)`, `flag_criteria(protocol, k=3)`, `optimize.search.optimize(protocol, max_edits=3)`; once they stop raising `NotImplementedError` the fixtures drop out by themselves. Check the real `Fix.edits` use `target_id` of the same protocol (accept relies on that).
2. `live.record_prediction` / `record_feedback` call the T21 ledger signatures; verify rows appear in `predictions` / `feedback` and that `/audit` shows them.
3. The fast re-run needs a fitted surrogate at `DATA_DIR/models/surrogate.json` (T24). Until it exists `/fixes/accept` returns `optimizer_estimate`. With it: check `Surrogate.score(protocol, eligible_df)` accepts the eligible rows (that is what is passed) and that before and after rates look sane. The quick re-run is untested against the real surrogate and model (only against stand-ins at the `clinova.api.live` seam).
4. `trial_versions` is empty, so the reveal timeline shows no events on live trials until T11's history pass runs.
5. The backtest of a trial with changed eligibility parses the current text with Gemini (cached in `llm_cache`).

## How to run
```
uv run python -m clinova.api --port 8000                     # database and Gemini from .env
CLINOVA_API_NO_DB=1 uv run python -m clinova.api --port 8000   # offline, fixtures
CLINOVA_API_URL=http://127.0.0.1:8000 uv run python -m clinova.app
uv run python -m clinova.app.screenshots --url http://127.0.0.1:8501
```
`CLINOVA_MODE=demo` makes cache misses fall back to fixtures per stage instead of calling Gemini.
