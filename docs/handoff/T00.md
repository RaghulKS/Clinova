# T00 handoff: bootstrap, frozen contracts, merged spikes

## What works
- **Package** `clinova/` (Python 3.11, uv, hatchling) with subpackages ingest, parse, cohort, simulate, model, optimize, loop, api, app, common. Dependencies are locked in `uv.lock`. `.python-version` is 3.11.
- **`clinova/contracts.py` (contracts-v1)**: every shared model, plus vocabularies (`ClinicalField`, `Operator`, `FIELD_SPECS` with canonical units and plausible ranges, `STAGES`, `HISTOLOGIES`, `BIOMARKER_STATUSES`, `RACE_ETHNICITIES`, `PROCEDURE_VOCAB`, `LOCKED_BY_DEFAULT`, `COHORT_COLUMNS`) and the JSON shapes for `docs/metrics.json` and `docs/replay.json`. Guide: `docs/CONTRACTS.md`.
- **`clinova/common/config.py`**: pydantic-settings. Reads `.env` from the tree root, then from the main clone. Model ids: `gemini-3.5-flash-lite` and `gemini-embedding-2` (768-d), checked against ai.google.dev on 2026-10-10. Model ids appear only in this file. Also `amendment_cost(phase)`.
- **`clinova/common/llm.py`**: the only Gemini entry point. Sync and async `generate_json` / `embed`, cached in `llm_cache`, demo mode is cache-only (`CacheMiss`), backoff on 429/5xx, `llm_usage` rows keyed by an API-key fingerprint, `BudgetExceeded`. A live smoke test (namespace `t00_smoke`, 2 calls) worked end to end against Gemini and Tiger Cloud.
- **`clinova/common/db.py`**: psycopg pool, `get_conn()`, `apply_schema()`, and `python -m clinova.common.db apply`.
- **`db/schema.sql`**: applied to Tiger Cloud twice (idempotent). Server: PostgreSQL 18.6, TimescaleDB 2.30.2, pgvector 0.8.7. 15 tables, 7 hypertables, an HNSW cosine index on `trial_embeddings`, and a real-time continuous aggregate `prediction_scores_monthly`.
- **Stubs** with final signatures and docstrings for every entry point named in the task, plus a `__main__.py` CLI per subpackage. `tests/test_stubs.py` checks they exist.
- **Fixtures** in `tests/fixtures/` (see `docs/CONTRACTS.md`), round-tripped and cross-checked by `tests/test_contracts.py`.
- **Packaging**: `Makefile` (`check`, `db-apply`, `up`, `down`), placeholder `docker-compose.yml` using `timescale/timescaledb-ha:pg18.6-ts2.30.2` (bundles pgvector; matches Tiger Cloud), MIT `LICENSE`, stub `README.md`, and GitHub Actions `.github/workflows/ci.yml` running `make check` in demo mode.
- **Spikes merged**: see "Spikes" below.


## Stubbed or faked
- Every product function raises `NotImplementedError` until its owner task fills it in.
- Fixture numbers (risk scores, metrics.json, replay.json) are illustrative and are marked "FIXTURE" in the files.

## Decisions
- `TrialRecord` keeps first-version design fields and LABEL-SIDE outcome fields in one row. The two eligibility texts are separate fields (`eligibility_text_first`, `eligibility_text_current`), so the leakage boundary is visible in the names.
- `phase2_3` uses the Phase III amendment cost.
- `screen()` returns `(bool mask, Funnel)` to meet the 50 ms target. Per-persona `ScreenResult`s come from `screen_results()`.
- `apply_edits(rules, edits)` handles rule edits only (as T13's task file says). Visit edits are applied by the optimizer.
- `simulate_trial` returns one `SimRunSummary` per seed, because `sim_runs` holds one row per seed.
- `feedback.user` is named `user_name` (`user` is a reserved word in SQL).
- `prediction_scores` and `predictions` carry `context` (live, replay, ...) and `model_version`, so the replay's retrained and frozen arms can share the continuous aggregate.
- Hypertable chunk intervals are wide (1 month to 1 year) because the data spans decades and volumes are small.
- pytest runs with `--import-mode=importlib` and `pythonpath=["."]`, so test files in different `tests/<module>/` folders may share basenames without `__init__.py`.
- `sim_features` is left to T24, as in ARCHITECTURE.md section 6.
