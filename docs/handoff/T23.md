# T23 protocol optimizer handoff

## Status and what works

Publish as **partial**. The implemented optimizer returns and persists three
distinct demo edit sets with cohort ranges and explicitly heuristic expected
amendment dollars in under 10 seconds. Production scorer and precedent interfaces
are ready, but fitted T22/T24 artifacts, completed-trial evidence coverage and
adjacent parsed history are unavailable. No precedents or model draws are invented.

- `optimize/edits.py`: empirical relaxation candidates read from other actual
  NSCLC trials' `criteria_rules`; numerical, ordinal, categorical and exclusion
  semantics are validated. Author locks and default pregnancy/consent locks never
  change. Rule drops, explicitly optional contact cuts, same-day adjacent merges
  and explicitly permitted compatible remote visits are supported. Edits are pure
  and invalid/overlapping batches fail without changing the input.
- `optimize/search.py`: Optuna NSGA-II, at most three edits per candidate, with
  cached cohorts, rule masks and demographic screening results. Objectives are
  `eligible_frac * enroll_rate * (1 - p_shortfall)`, lower dropout and diversity.
  The Pareto front is deduplicated by canonical edit set. Exact dropout ties prefer
  distinct representatives; balance selects the nearest remaining point to the
  normalized ideal. Tiny fronts can still share a combination, explicitly noted.
  If NSGA-II initialization or search fails, all admissible singles/pairs are
  enumerated and the Pareto front is taken directly. Invalid scorer output fails
  visibly rather than being silently discarded as an unsafe edit.
- `optimize/scoring.py`: `Scorer`, validated `Score`, explicitly uncalibrated
  `StubScorer`, and production `ModelScorer`. The production adapter automatically
  uses the frozen T22 `predict.score(protocol, sim=...)` and T24
  `Surrogate.load`/`.score` interfaces when their modules/artifacts are available.
  It detects the optional `predict.score_samples` hook and accepts injected
  paired draws. A missing bootstrap artifact leaves a fitted point model intact.
  Missing surrogate artifacts do not incur a cold sklearn import.
- Ranges reevaluate original and edited protocols on seeds 42–46. Amendment
  uncertainty uses matched bootstrap model indices, never marginal CI endpoint
  subtraction. Before/after draw counts and counts across seeds must match.
  Dollars are `max(0, -delta_p_amend) * config.amendment_cost(phase)`, labeled
  expected value. Current real runs have **zero fitted bootstrap models**;
  persisted summaries explicitly say ranges cover five cohort seeds only.
- `optimize/precedents.py`: completed comparable NSCLC trials are selected using
  pgvector, with completion/NSCLC filtering before the neighbor limit. Citations
  require verified first-version restrictions supporting the proposed relaxation.
  `widening_report` implements the exact original-threshold denominator and the
  earliest verified field widening's months after start. Unknown fragments,
  invalid units, mismatched snapshots and missing adjacent versions cannot
  establish a precedent or an amendment. Coverage gaps are reported separately.
- `optimize/store.py`: reads first-version rules and design metadata, builds the
  estimated schedule, and writes only the owned `fixes` table. Deterministic
  IDs include the original protocol snapshot, seed, label and edit set; reruns
  UPSERT the same rows. Unparseable rules never infer the cohort setting.
- CLI defaults to selected demo NCT03232892 and supports explicit trial, seed,
  search size, cohort size, output JSON, fixture, no-persist and benchmark options.
  JSON includes the exact protocol snapshot and hash for reproducibility. The
  benchmark checks search time, load/persistence time, and three returned fixes.

## Run it

From `.worktrees/T23`, with `.env` linked to the main clone:

```bash
uv sync --frozen
uv run python -m clinova.optimize --benchmark --output .data/T23-demo-final.json
uv run python -m clinova.optimize --trial NCT03232892 --no-persist
uv run python -m clinova.optimize --fixture --no-persist --benchmark
make check
```

An explicit offline synthetic run uses `--fixture` or injected evidence/scorer
arguments to `optimize_with_report`. The frozen `optimize(...)` entry point raises
`NotImplementedError` for `FIXTURE-*` IDs so the existing API fixture handler labels
those responses accurately without querying production data. The API owner's
additional DB-preflight change is recorded in `docs/contract_changes/T23.md`.

Historical widening query (actual original CrCl threshold, or the task's 60 example):

```python
from clinova.optimize.precedents import widening_report
from clinova.optimize.store import load_protocol

protocol = load_protocol("NCT03232892")
rule = next(r for r in protocol.rules if r.field == "crcl_ml_min")
print(widening_report(protocol, rule).model_dump_json(indent=2))
print(widening_report(protocol, rule.model_copy(update={"value": 60})).model_dump_json(indent=2))
```
