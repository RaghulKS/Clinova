# T12 handoff: criteria parser, visits, rule diff, embeddings

Status: **partial** (code complete and tested; batch parsing still running in the background; T11 was still loading trials).

## What works
- `parse.parser.parse_protocol`: one Gemini call (`llm.generate_json`, namespace `parse`, seed 0, temp 0) returning `ParseOut` (`parse/schema.json` is its JSON schema, checked by a test). Post-processing: renumber ids (I1.., E1..), `sanity()` range/operator/vocabulary checks (violations become `field=other`, `parse_status=unparseable`, note "sanity check: ..."), `locked=True` on pregnancy and consent_capacity, canonical unit set from `FIELD_SPECS`. Setting is inferred by the model. Visits from `schedule_text` via `extract_visits`.
- `parse.visits`: `extract_visits` (Gemini, namespace `parse_visits`, not exercised against live Gemini yet, only the estimator is tested); `estimate_visits(trial)` is deterministic (screening, cycle visits every 21 days or 28 for oral-only, imaging every 6 weeks phase 2 / 9 weeks phase 3, day 8 safety labs that can be local, capped at day 365), all `estimated=True`.
- `parse.diff.diff_rules`: pure. Per field it evaluates each version's pass-set on a grid (vocabulary, or all thresholds, midpoints and integers) and compares by containment: relaxed / tightened / removed / added. An incomparable change falls back to grid size (marked `ponytail`). Closedness (`>` vs `>=`) is honoured.
- `parse.embed`: `embed_trials(nct_ids=None)` (first-version text prefixed by the title, 768-d, namespace `trials_embed`, resumable, test split first) and `nearest(query, k, exclude=())` by pgvector `<=>`.
- Gold set: `tests/parse/gold/gold.json`, 12 real NSCLC eligibility texts fetched from the CT.gov API (`scripts/fetch_gold_candidates.py`) and annotated by hand by reading them (`tests/parse/gold/build_gold.py`; 113 annotated rules; vague conditions like "adequate organ function" are deliberately not annotated; value `"*"` = field expected, threshold ambiguous). Evaluator: `python -m clinova.parse.evaluate --out docs/parse_gold_metrics.json`.
- `make check` equivalent (`uv run ruff check . && uv run pytest -q`): 73 passed.

## Problems
- Gemini returns 429 RESOURCE_EXHAUSTED ("exceeded your current quota") on this key under load shared with other agents; failures are logged as `FAIL <nct>` and retried by the next round. Batch uses 4 worker threads.
- `common/llm.py` (integrator file): sync `generate_json` called from many threads sometimes raises `RuntimeError: Cannot send a request, as the client has been closed` (the `lru_cache`d `genai.Client` is closed when another thread's per-call event loop ends). Proposed: use `agenerate_json` from a single event loop in bulk jobs, or build the client without sharing across `asyncio.run` loops. Those trials are simply retried in the next round.
- ~44% unparseable is expected for NSCLC text (vague "adequate function", washouts, drug-specific rules); they are flagged, never guessed.

## Decisions
- LLM output uses `value_json` (JSON string) instead of the union `RuleValue` to keep the Gemini response schema simple.
- Exclusion rules are written as the condition being excluded (matches CONTRACTS semantics); "any CNS metastases" = `brain_mets in [treated_stable, untreated]`.
- Diff ignores unparseable rules and `other`.
