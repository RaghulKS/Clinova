# T33: offline tests and CI

## What works

- Shared pytest setup isolates data/models/settings from the main clone and `.env`,
  clears the Gemini key, defaults to demo mode, and disables API database access.
- An autouse guard rejects Python Internet socket connections, UDP sends, DNS
  resolution, and native psycopg connections. Caught attempts also fail teardown.
  The sole socket exception is the original standard-library `socketpair()` call:
  Windows asyncio uses its local loopback wakeup pipe. Direct loopback connections
  remain blocked. Regression checks exercise the guard and the local pipe.
- Hand-computed examples cover AUC pair ordering/ties, paired AUC differences,
  Brier loss, reliability endpoints/empty bins, and hit-rate/random/marginal
  denominators. Additional parser schema/sanity and combined/ordinal/strict-boundary
  `diff_rules` checks supplement the existing module tests.
- Existing screen properties, golden funnel, integrity/leakage, demo LLM cache,
  and all twelve API route tests remain enabled. Two previously incomplete offline
  tests now use explicit engine fakes and an in-memory HTTP error transport.
- GitHub Actions runs Python 3.11, frozen uv sync, `make check`, and publishes JUnit
  results. A separate nine-minute Docker smoke job builds/starts API and app,
  submits the seeded demo trial to `/runs`, requires completion without fixture
  fallback, and always logs/cleans up.

## How to run and validation

```bash
uv sync --frozen
make check
# Windows host without GNU make: exact lint/test recipes, with local artifact paths
uv run ruff check .
uv run pytest -q --basetemp=.data/pytest-final --junitxml=.data/test-results.xml
```

`uv sync --frozen` and `uv run ruff check .` passed. The final full offline pytest
run passed **502 tests in 69.77 seconds**, with twelve dependency warnings and no
skips/xfails. JUnit output is in `.data/test-results.xml` (local, not committed).
GNU make is unavailable on this host; its two recipes are executed directly here.
CI executes the literal `make check` on Ubuntu. Branch CI verification is pending
the first task-branch push.

Workflow YAML parsing, embedded smoke Python compilation, and four mocked HTTP
paths passed: queued-to-done success, failed-run rejection, fixture rejection,
and timeout rejection. `git diff --check` passed.

## Numbers produced

These regression examples are synthetic arithmetic, not clinical/model results:
AUC 0.75 (three of four ordered positive/negative pairs); tied AUC 0.875;
Brier 0.158125; hit rate 0.5 over two evaluable trials; random baseline 0.5;
marginal baseline 1.0. No trained metrics or acceptance claims were changed.

## Decisions and open issues

- No product code changed. No new product bug needed an xfail or owner patch.
- Docker is unavailable locally. T31 packaging is not in this branch. Until its
  Dockerfile is merged, the smoke job explicitly reports skipped Docker steps.
  Once present, compose/schema/seed/HTTP failures fail the job; the gate does not
  suppress failures of existing packaging. See `docs/contract_changes/T33.md`.
- A job timeout is a bound, not measured cold-build performance. Docker acceptance
  and the below-ten-minute cold build remain pending actual container CI.
- Existing dependency deprecation warnings are retained; no dependencies changed.
