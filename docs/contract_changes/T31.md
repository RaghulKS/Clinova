## 2. API: serve frozen optimizer results in demo mode (proposed, T32 owns clinova/api)
Until applied, `scripts/demo_serve.py` (the API container's entry point) monkeypatches `live.optimize` with the same logic, so nothing breaks either way. Proposed diff for `clinova/api/live.py`:

```python
def optimize(protocol, max_edits=3):
    _need_db()
    if get_settings().CLINOVA_MODE == "demo":          # the real optimizer takes ~2 minutes per trial
        path = REPO_ROOT / "docs" / "demo_results" / f"{protocol.trial_id}_optimize.json"
        if path.is_file():
            saved = json.loads(path.read_text(encoding="utf-8"))
            if saved["protocol"]["rules"] == [r.model_dump(mode="json") for r in protocol.rules]:
                return [Fix.model_validate(f) for f in saved["fixes"]]
    from clinova.optimize.search import optimize as _optimize
    return _optimize(protocol, max_edits=max_edits)
```
(needs `import json`, `from clinova.common.config import REPO_ROOT, get_settings`, `from clinova.contracts import Fix`). After applying, delete `scripts/demo_serve.py` and point the Dockerfile/compose commands back at `python -m clinova.api`.
