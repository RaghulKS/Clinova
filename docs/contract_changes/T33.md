# T33 CI packaging coordination

## T31 integration required

T33's checkout still has the G2 database-only `docker-compose.yml` and no Dockerfile.
The `demo-smoke` CI job therefore reports a notice and skips its Docker steps until
T31's Dockerfile is merged. This is a temporary integration gate, not Docker acceptance.
The existing ruff/pytest job remains enabled.

T31's uncommitted worktree was inspected read-only on 2026-10-11. Its draft already
provides the exact interface the smoke job requires; no product change is requested:

- Merge T31's `Dockerfile`, `.dockerignore`, `docker-compose.yml`, `db/seed/`,
  `scripts/seed.py`, and `scripts/demo_serve.py` together.
- `CLINOVA_MODE=demo GEMINI_API_KEY='' docker compose up --build --detach --wait
  --wait-timeout 120 api app` must build the application image, start the local
  TimescaleDB, complete seed loading, and make both API/app health checks pass.
- The API must expose port 8000, report `mode=demo` and `db=true` at `/health`,
  and accept `POST /runs` with `{"nct_id":"NCT03232892"}` (default cohort/seeds).
- Polling its returned `status_url` must reach `stage=done` within 90 seconds,
  with `source=live` (cached real demo pipeline rather than fixture fallback),
  the requested trial id, a funnel, simulations, three risks and three fixes.

The job allows nine minutes total: at most six minutes for image build/start,
two minutes for the HTTP smoke, and one minute for logs/cleanup. The total job
timeout is the hard bound; runtime below it has not yet been measured.

## Validation limits

Local validation: YAML parsed successfully, the embedded Python compiled, and
mocked HTTP self-checks exercised queued-to-done success, failed-run rejection,
fixture-fallback rejection, and timeout rejection. `git diff --check` passed.

The smoke request and expected source match T31's draft `tests/demo/test_demo_mode.py`.
Docker is not installed in this Windows environment, so neither an image build
nor a compose run was executed here. GitHub Actions execution and cold-build
duration remain unverified. The workflow deliberately uses no API key; HTTP
smoke alone does not prove zero outbound network attempts (T31's offline tests
cover that separately).
