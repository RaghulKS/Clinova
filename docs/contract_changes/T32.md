# T32 contract change requests

## 1. `make check` cannot load LightGBM on a Mac without Homebrew's libomp

**Seen on:** the B-claude machine at hour 6.4. `lightgbm` imports `lib_lightgbm.dylib`, which needs `@rpath/libomp.dylib`. Homebrew is not installed, so the library is missing. `make check` then stops at collection with four errors (`tests/integrity/test_integrity.py`, `tests/loop/test_checker.py`, `tests/loop/test_replay.py`, `tests/model/test_model.py`). They are all `OSError: dlopen(...)`.

**Confirmed workaround:** scikit-learn's wheel ships `sklearn/.dylibs/libomp.dylib`. With that folder on `DYLD_FALLBACK_LIBRARY_PATH`, the full suite passes (481 passed):
```
DYLD_FALLBACK_LIBRARY_PATH=$PWD/.venv/lib/python3.11/site-packages/sklearn/.dylibs .venv/bin/python -m pytest -q
```
Do not route this through `/usr/bin/make`. macOS SIP removes `DYLD_*` variables when it starts a protected binary, so the variable is lost before `make` runs its children.

**Proposed change (owner: integrator, `Makefile`):**
```make
# macOS without Homebrew libomp: borrow scikit-learn's copy for LightGBM (no-op elsewhere)
SKLEARN_OMP := $(shell uv run python -c "import sklearn,os;print(os.path.join(os.path.dirname(sklearn.__file__),'.dylibs'))" 2>/dev/null)
test:
	DYLD_FALLBACK_LIBRARY_PATH="$(SKLEARN_OMP)" uv run pytest -q
```
This still runs into the SIP problem when `make` itself is the system binary. The more robust alternative is a few lines in `clinova/common/` that preload the library with `ctypes` before importing lightgbm. That did **not** work in my test, because dyld matches by install name. Re-executing with the variable set does work. The API now does that in `clinova/api/__main__.py` (my folder), so `python -m clinova.api` serves the real model on such a Mac.
