# T24 integration requests and provider blocker

## Shared data directory discovery

Observed: `scripts/orch.sh start` created the linked worktree as CodexSandboxOffline. Escalated Python runs as rghls, so Git returns 128, "detected dubious ownership". `common.config._main_root()` catches this and silently treats the worktree as the main clone. The resulting default DATA_DIR differs across task invocations.

Proposed exact change in `clinova/common/config.py` (integrator owns this file):

```diff
-            ["git", "rev-parse", "--path-format=absolute", "--git-common-dir"],
+            ["git", "-c", f"safe.directory={REPO_ROOT.as_posix()}",
+             "rev-parse", "--path-format=absolute", "--git-common-dir"],
```

The exception is scoped to the repository from which trusted application code is running; it does not change global Git trust. Add a regression test asserting linked-worktree discovery under the owner mismatch. Until integrated, T24 commands export process-scoped `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=safe.directory`, and `GIT_CONFIG_VALUE_0=<absolute T24 worktree>`.
