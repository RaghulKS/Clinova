# T21 shared contract proposals

## Audit view: apply to db/schema.sql at Gate 2

The view was deployed and round-trip verified on Tiger Cloud with `ledger.ensure_audit_view()`.
The base schema must create it too so a new deployment has the same Audit surface.
Apply this exact diff after the feedback hypertable definition (predictions already exists):

```diff
--- a/db/schema.sql
+++ b/db/schema.sql
@@
 SELECT create_hypertable('feedback', by_range('created_at', INTERVAL '1 month'), if_not_exists => TRUE);
+
+CREATE OR REPLACE VIEW audit_log AS
+SELECT COALESCE(f.created_at, p.predicted_at) AS event_at,
+       COALESCE(f.trial_id, p.trial_id) AS trial_id,
+       p.prediction_id, p.model_version, p.target, p.p, p.ci_low, p.ci_high,
+       p.context, p.predicted_at,
+       f.feedback_id, f.user_name, f.target_type, f.target_id, f.decision,
+       f.rating, f.comment, f.created_at
+FROM predictions p
+FULL OUTER JOIN feedback f
+  ON f.target_type = 'prediction' AND f.target_id = p.prediction_id
+ AND (f.trial_id IS NULL OR f.trial_id = p.trial_id);
```

## T22 swap at Gate 2

`origin/task/T22-model` did not exist at T21's final availability check. The explicitly
named `clinova.loop._model` implements the permitted temporary logistic `train(df, cfg)`
bundle and predicts using the same selected first-registration fields in both arms.
Its versions always begin `T21-placeholder-logistic-`; it is not the final Clinova model.

After T22 lands, replace the trainer and probability call sites in `loop/checker.py`
and `loop/replay.py` with `model.train.train` and T22's matching feature/calibration
path. Required replay config: save=False, no bootstraps, fixed hyperparameters in both
arms, no test-split training, and only outcomes observed by the simulated cutoff.
Regenerate replay.json / replay.png and refresh the continuous aggregate. Do not quote
the current placeholder numbers as final T22 validation. This is a required integration
step, not a request to change the shared public train signature.

For the operational checker, T22's trainer should publish its saved/latest bundle after
the threshold is crossed. The current placeholder is saved only under DATA_DIR/loop;
it deliberately does not replace the API's future final T22 model bundle.
