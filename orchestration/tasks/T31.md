# T31 Demo mode, seed, Docker, Tiger Cloud

Owns `docker-compose.yml`, `Dockerfile*`, `db/seed/`, `scripts/` (except orch.sh). Read ARCHITECTURE.md section 9 and `docs/gate2_report.md`.

1. **Warm the cache.** In live mode, run the full app flow (parse, run, optimize, accept each of the three fixes) for the demo trial, both backups and the fixture draft protocol. Then prove demo mode reproduces identical results with `CLINOVA_MODE=demo` and no `GEMINI_API_KEY`, with a test that fails on any network call.
2. **Seed.** Export what demo mode needs (trials, trial_versions, criteria_rules, trial_embeddings, sim_runs and persona_outcomes for the demo trials, sim_features, predictions, prediction_scores, outcomes, fixes, llm_cache, empty feedback) plus `models/v1.0`, compressed into `db/seed/`. Over 90 MB → Release asset plus `make seed` with a checksum.
3. **Docker.** Dockerfiles for api and app (python:3.11-slim, uv, non-root). Compose: db loads schema + seed on first start; api and app with healthchecks and depends_on; `loop` and `mirofish` behind profiles, off by default. Target: clean clone → `docker compose up` → app ready at localhost:8501 in under 3 minutes.
4. **Tiger Cloud.** `make tiger-load` loads schema and seed into the service in `DATABASE_URL`; the stack runs against Tiger Cloud by setting `DATABASE_URL`. The video uses Tiger Cloud; judges use local TimescaleDB.
5. **Clean-path test.** Clone into a temp folder, no `.env`, `docker compose up`, run the demo trial through the app (Playwright). Fix what breaks; record the time.

**Done when:** the clean-path test passes and `make check` passes.
