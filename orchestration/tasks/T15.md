# T15 API and app shell on fixtures

Owns `clinova/api/` and `clinova/app/`. Read ARCHITECTURE.md section 8, `docs/CONTRACTS.md` and the fixtures. **Goal:** the full experience running end to end on fixture data, so the engine drops in at the gates without UI work.

Fan out two parallel parts:

1. **API.** FastAPI in `api/main.py`, response models from `contracts.py`. Routes: POST /protocols/parse, POST /runs (returns run_id), GET /runs/{run_id} (status by stage + results), GET /trials/{nct_id}/backtest, POST /optimize, POST /feedback, GET /validation, GET /replay, GET /pulse/{nct_id}, GET /audit, GET /health. Each route calls the real module and falls back to fixtures on NotImplementedError, returning `source: fixture|live|cache`. TestClient tests for every route.
2. **App.** Streamlit in `app/`, talking to the API only through `app/client.py`. Input: paste eligibility text and schedule, or an NCT ID. Parsed rules in an editable table (field, operator, value, unit, raw text, lock toggle; unparseable rows highlighted), then **Run Clinova**. One results screen, three panels: Funnel (plotly; biggest exclusion highlighted), Risk (three cards: probability, range, confidence badge, top drivers; each flag says where, why, what to do), Fixes (effects on enrollment speed, dropout, diversity; ranges; dollar value; precedents; Accept/Reject → /feedback). Tabs: Validation, Replay, Community Pulse, Audit log. A small "fixture data" tag shows whenever `source == fixture`.

Design: calm, clinical, one accent colour, readable at 1920×1080. Wording frames everything as suggestions for the protocol author. Run it, take Playwright screenshots of every view into `docs/screens/`, look at them, fix what looks off.

**Done when:** API and app run locally on fixtures, screenshots exist, and `make check` passes.
