# T21 Learning loop, ledger, outcome checker, replay

Owns `clinova/loop/` and tables `predictions`, `prediction_scores`, `outcomes`, `feedback`. Read ARCHITECTURE.md 5.9, 6, 7 and `docs/gate1_report.md`. Use `model.train.train(df, cfg)` from T22 when it lands on origin (`origin/task/T22-model`); until then use a small logistic placeholder with the same signature, and note the swap for Gate 2.

Fan out three parallel parts:

1. **Ledger and feedback.** `loop/ledger.py`: `record_prediction` (every score with model_version and timestamp) and `record_feedback` (fix accept/reject, persona-realism rating, comment, user). An `audit_log` view joining both, for the Audit tab.
2. **Outcome checker.** `loop/checker.py` re-fetches `pending` trials via `clinova.ingest.ctgov`, writes `outcomes` when a trial ends (observed_at = completion or termination date), applies the labelling rules from T11, scores matching predictions into `prediction_scores`, and triggers retraining when 25 or more new outcomes arrive. CLI `python -m clinova.loop check`.
3. **Replay.** `loop/replay.py`: freeze at 2019-12-31, training on trials whose outcome was observed by then (first-version features only). Step monthly 2020-01 to 2023-12: score trials whose outcome arrives in the next 6 months with the current model, record those predictions with `predicted_at` = that month; then add the month's new outcomes and retrain. Run the same windows with a never-retrained model. Output `docs/replay.json` (monthly AUC and Brier for both, with counts) and `docs/figures/replay.png`. Write replay predictions and scores to the ledger so the continuous aggregate shows them. If retraining doesn't beat the frozen model, say so plainly.

**Done when:** the ledger and checker work against Tiger Cloud, the replay ran (with the placeholder model if T22 isn't ready), and `make check` passes.
