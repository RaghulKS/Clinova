# T25 API and app wiring

Owns `clinova/api/`, `clinova/app/`, table `drafts`. Read the handoffs on main and `docs/gate1_report.md`. Model, optimizer and loop are being built in parallel on other branches; wire to their contract signatures, keep fixture fallbacks, and list what Gate 2 must swap.

1. POST /runs runs the real pipeline as a background job: parse (or load the first version for an NCT ID), cohort, screen, agents, score, flags, optimize. Progress by stage. Every prediction goes through `loop.ledger.record_prediction`.
2. GET /trials/{nct_id}/backtest returns the first-version run plus version-history events for the reveal (when and how eligibility, enrollment target and status changed).
3. Accepting a fix calls `loop.ledger.record_feedback`, applies the edits, re-runs screen, score and surrogate (fast path, no new Gemini calls) and returns before-and-after numbers.
4. /validation reads `docs/metrics.json` and figures; /replay reads `docs/replay.json`; /pulse reads the cached MiroFish report; /audit reads the audit view.
5. App: progress view during runs, reveal timeline for the backtest, before-and-after after accepting a fix. Keep the "fixture data" tag.

Re-take Playwright screenshots, review them, fix what looks wrong.

**Done when:** a live run of the demo trial works through the API with whatever real modules are merged, and `make check` passes.
